How to use it

And what it does and doesn't protect against.

← Back to the generator

The problem

"Hi Mum, I've lost my phone, this is my new number, can you send me £300?" used to be a text. Now it can be a phone call in your child's actual voice, cloned from a TikTok clip. Old-fashioned family code words help, but a fixed word can be overheard, guessed, or coaxed out of someone once and reused forever.

The idea

Authenticator apps already solve "prove you hold a secret without saying the secret". Two phones holding the same secret show the same six-digit code at the same time, and the code changes every thirty seconds. So the person on the line can read you their code, and you check it against yours. A scammer with a cloned voice can't produce it.

Setting it up

  1. Do it in person, or on a call you already trust. You're about to share a secret, so don't do it over a channel you're worried about.
  2. Open the generator and type a label such as "Mum & Rob". That's just the name your authenticator app shows.
  3. Both of you scan the same QR code with your authenticator app. Any app that does "two-factor codes" works: Google Authenticator, Microsoft Authenticator, Authy, 1Password, Bitwarden, Apple Passwords, Aegis, Ente Auth.
  4. Check the numbers match — both apps and the page should show the same code.
  5. Close the page. If you ever need to set up the same pair again, generate a fresh secret and re-scan; don't try to keep the old one.
  6. Repeat for each pair. Mum & Rob, Mum & Sarah, Rob & Sarah. One secret per pair, not one for the whole family.

On a call

Agree in advance that either of you can ask at any time, and that asking is never rude. Then, when something feels off:

"Before we go on — read me the code."

They open their app and read six digits. You open yours. Same number? Carry on. Different, or they can't do it, or they say the app isn't working, or they get upset that you asked? Hang up and call them back on the number you already have.

It also works the other way round: if you ring a relative and they're not sure it's you, read them your code.

What it protects against

  • Voice-cloned calls pretending to be a family member
  • "New number" messages asking for money
  • Anyone who has learned your old fixed code word

What it doesn't protect against

  • A stolen or unlocked phone. Whoever holds the phone holds the codes. Keep a lock on it, and if a phone is lost, generate new secrets for every pair it was in.
  • Someone relaying codes live. If an attacker is on a call with the real person at the same moment and asks them for their code, they can pass it on within the thirty seconds. Rare, but possible. If a code arrives suspiciously late, ask for the next one.
  • Pressure. The whole point is to give you a reason to pause. If someone is pushing you to skip the check, that's the signal.
  • Telling you who it is. Both people in a pair share the same secret, so a code proves "someone in this pair", not which one. That's fine when there are two of you; it's why you shouldn't use one secret for a group.

How it works, for the curious

It's standard TOTP (RFC 6238): a random 160-bit secret, HMAC-SHA1 over the current 30-second window, six digits. The page generates the secret with your browser's cryptographic random number generator and packages it as an otpauth:// URI inside the QR code, which is exactly what any website does when it sets up two-factor login. Nothing is sent to a server — there is no server — and the page carries a Content Security Policy that forbids it from making network requests at all. You can read the source, or save the page and run it from your own computer with the Wi-Fi off.

No accounts, no cookies, no analytics, no server. Everything happens in your browser.
